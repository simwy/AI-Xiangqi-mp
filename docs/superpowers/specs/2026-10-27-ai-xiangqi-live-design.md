# AI 象棋直播间首版设计

日期：2026-10-27。状态：用户已接受当前竖屏 UI，并要求提交 Git；对局服务等架构内容仍为后续实现建议。独立预览保存在 `ui-preview/`，本文尚未代表完整功能已经实现。

## 已确认的目标

- 使用现有 uni-app / Vue 3 项目，首先交付网页版本，核心功能考虑微信和抖音小程序兼容。
- 全站仅一场正在进行的 AI 对局。无人观看时仍运行，结束后自动开启下一场。
- 两位棋手都是通过 OpenAI 兼容 API 接入的大模型。
- 棋盘上下分别显示对应模型的形象图片、名称及状态。
- 提供女性 AI 语音解说、字幕、落子音效、移动轨迹和战术特效。
- 底部仅保留历史棋局、从头回看、下局投票三个业务按钮。
- 支持从头逐步回看到当前进度，后续可用画面进行抖音直播。

## 首版范围与实现者建议

以下为实现者建议，并非用户已指定的技术选型。首版完成可本地运行的前后端、合法棋局规则、真实 API 适配、历史回放、持久化及投票。不包含平台上架、服务器购买、自动推流、支付或数字人唇形动画。

保留已有模板页面和模块，新增观战首页并替换默认入口与模板底栏。新首页不依赖 uniCloud 登录或数据库初始化，避免未绑定云空间时无法观战。

前端使用 uni-app 的 view、text、image、button、scroll-view 和通用 CSS；通用业务不使用 DOM、浏览器存储或浏览器专用音频接口。API 封装使用 uni.request，音频封装使用 uni.createInnerAudioContext，存储使用 uni 存储接口。网页直播展示模式可使用条件编译。避免把复杂 SVG、WebGL 或浏览器专用画布作为核心棋盘依赖。

## 服务端与持续对局

建议新增独立 Node.js 服务（Node 24 LTS、内置 SQLite、单实例运行），由常驻循环驱动对局；HTTP 请求仅查询状态或提交投票，不驱动落子。部署要求常驻进程和持久化磁盘，不能以网页定时器或会休眠的短时云函数代替。

使用 SQLite 事务保存当前局、落子事件、结果和投票。每步有递增序号和服务端时间，快照与事件一起提交。进程重启从已提交局面恢复；重复或迟到的模型响应不能再次落子。首版仅允许一个写入实例，后续横向扩容需引入跨进程锁和共享数据库。

建议接口包括状态、按序号补取事件、历史列表、单局棋谱、候选模型和投票。首版使用约 2 秒增量轮询（隐藏页面暂停，重新显示补齐），兼容三个目标平台；断线显示同步状态，不能假装实时。API 基址可配置，生产使用 HTTPS，并配置小程序域名白名单。

## 模型接入与规则

模型配置保留 id、名称、头像路径、baseURL、model、服务端密钥引用和超时。首次真实运行至少需要两个有效模型配置；候选阵容只包含已启用配置。模型名称与实际调用配置绑定。

服务端按当前局面生成合法动作列表，发送棋盘、最近棋谱和动作编号，请模型只返回所选动作的结构化结果。规则覆盖车马炮象士将兵、蹩马腿、塞象眼、炮架、过河、九宫、将帅照面和不能自陷将军。

建议单次调用超时 45 秒，最多三次尝试；连续非法输出判负。单方独立请求超时耗尽判负；明确的共同供应商故障或配置错误进入暂停状态并退避重试，页面显示原因，不能自动制造落子。绝不暗中调用象棋引擎代下。

将死或无合法着法判负。首版使用明确标注的简化和棋规则：三次同局面且同走方、连续 120 半回合未吃子、总计 400 半回合；不宣称实现完整竞赛长将长捉裁定。规则阈值可配置，计入棋局记录。

## 页面与演出

用户补充确认：只需竖屏，网页亦保持同一竖屏构图，不做桌面信息面板或侧栏。尽力贴近参考截图的游戏场景、灰绿石质棋盘、厚实立体棋子和人物画面；避免仪表盘、卡片堆叠及普通网站按钮的观感。按上方棋手形象场景、棋盘、棋盘下沿三个游戏按钮、简洁解说字幕、下方棋手形象场景布局。历史棋局、从头回看、下局投票替换截图原有按钮，点击仅打开画面内浮层。双方均显示实际图片，不用字母头像代替；素材可配置。通过落子轨迹、落地反馈、思考状态、战术特效与适量环境动效提升直播观看体验，保持棋盘清晰。未提供形象时使用明确标注的临时素材，不冒充官方授权。参考截图裁切仅用于本地设计预览，正式发布替换成独立素材。

棋子移动展示起终点与轨迹，随后落地音效、报招、解说。模型思考状态由服务端提供。将军使用规则计算后的特效；叫杀仅在有战术搜索证明时显示，首版允许不显示未经证实的叫杀。报招使用规范着法处理前后同类棋子等歧义，不由解说模型猜。

进一步视觉调整（以用户最新更正为准）：三个按钮位于红方豆包 banner 下方的屏幕最底部，解说条在豆包 banner 上方，降低直播底部遮挡对核心画面的影响。双方形象都有轻微浮动或呼吸动效，名称与形象之间放完整金色发光圆环，展示本步思考时间及简短状态；不展示模型私有推理过程，真实状态来自服务端。绝杀演出区别于普通将军，使用蓄光、斩光、环形冲击波、短促位移震动、金色书法落印和收尾声音；尊重减少动态效果设置。设计预览手动触发的特效必须标明为演示，实际版本仅由已确认终局事件触发。

长距离移动不能匀速滑行：先抬起、放大与偏移阴影，再加速掠行、减速悬停，快速重落并轻微回弹；落地一刻同步短促棋盘震动、接触环和少量尘点。炮横跨六路作为验收样例。当前本地预览提供 48 kHz 木质撞击合成 WAV，取代原有扫频电子音，包含短时噪声接触、固定频率木质共振和短余响，不宣称为实物录音。音频预加载后与落地接触帧同步；正式小程序使用相同素材与平台音频封装，避免依赖网页音频合成能力。

走棋提示和预览操作提示统一放入解说框，取消棋盘下方独立提示行，并收紧间距。双方图片适度缩小，豆包保留完整头部、脖颈与上半身；人物浮动不能导致这些区域再次被裁切。

提供静音切换；首次点击启用音频，保留声音被平台限制的提示。解说失败不阻塞棋局。音频有优先级和有效期，报招与解说顺序播放，积压时丢弃过时解说；重连不补播全部旧语音。回放不与实时音频混播。

网页提供直播展示模式，隐藏交互面板，维持固定竖屏比例供 OBS / 直播伴侣采集；服务本身不负责抖音推流。

## 解说与语音

使用单独的解说文本模型配置，再接火山豆包语音合成。建议以“亲切女声 2.0”为试音候选，准确 voice id、资源权限及鉴权参数根据实际账号和官方文档核实，不预设可用权限。

解说输入仅包含已确认的局面、着法和规则事件；普通落子简短播报，关键局势适度展开，不虚构引擎分数或必胜判断。语音在服务端生成并缓存，通过音频 URL 提供给终端；固定报招和提示可预生成。文字模型与语音服务使用分别配置的凭据。

没有密钥时提供独立标记的本地演示模式，使用确定的合法示例棋谱。演示不调用付费接口，不显示为真实 AI 正在对战；真实服务断线不能自动切换成未标注的模拟直播。

## 回放与历史

历史页列出双方、开局时间、结果和步数，点击可查看完整棋局。当前局“从头回看”将本地游标置于初始局面，展示上一步、下一步、当前步 / 最新步及返回直播。

回看期间继续同步实时事件，但不改变用户游标；跨局开新场时仍可看完旧局，返回直播进入新的当前局。回放棋盘严格从持久化棋谱重建，不能用另一套随机过程替代。

## 下局投票

建议按当前局对应的下一场投票，每位观众每轮一票，选一名模型；前两名不同模型参赛，平票按稳定模型 id 排序，候选少于两名时使用配置的默认双方。开新局时事务性封存上一轮并创建新投票轮；临界请求不能落入错误轮次。下一局红黑按场次交替安排。

首版匿名网页身份使用持久化访客标识加服务端限流和去重，只是轻量投票，不能保证一人一票或抵抗清除存储。后续微信与抖音登录通过平台身份适配，在服务端换取统一会话。前端不得指定可信用户身份或修改总票数。

## 配置、安全与交付验证

密钥仅配置在服务端环境变量或本地忽略的配置文件中。提供无真实密钥的示例。投票和管理功能分离；不向观众开放修改 API 地址或触发新局的权限。限制文本长度、请求频率与外发目标，日志不记录 Authorization。

交付包含本地启动说明、服务端与前端配置示例、演示和真实运行区别、部署常驻要求。前端断线、语音错误及无模型配置均有明确提示。

自动化验证规则引擎的非法动作、被将军约束与终局；验证重启恢复、幂等落子、投票轮次和回放还原。构建验证覆盖 H5、mp-weixin、mp-toutiao；真实小程序设备、音频权限、平台登录和上架需要对应平台工具及账号，未实测项如实记录。密钥未提供前，真实模型对局与火山声音试听保持待验证。
