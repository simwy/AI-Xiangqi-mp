# AI 象棋直播间首版设计

日期：2026-10-27。状态：用户已接受当前竖屏 UI，已提交 Git，并要求完整开发。用户明确选择使用现有 uniCloud 数据库，并新增模型数据库配置及 think 开关需求。数据库已按“一局一条 JSON”及残局需求调整，本地前后端已按此方案实现；独立预览保存在 `ui-preview/`，不代表完整功能已经实现。

## 已确认的目标

- 使用现有 uni-app / Vue 3 项目，首先交付网页版本，核心功能考虑微信和抖音小程序兼容。
- 全站仅一场正在进行的 AI 对局。无人观看时仍运行，结束后自动开启下一场。
- 两位棋手都是通过 OpenAI 兼容 API 接入的大模型。
- 棋盘上下分别显示对应模型的形象图片、名称及状态。
- 提供女性 AI 语音解说、字幕、落子音效、移动轨迹和战术特效。
- 底部仅保留历史棋局、从头回看、下局投票三个业务按钮。
- 支持从头逐步回看到当前进度，后续可用画面进行抖音直播。
- 每局完整归档：逐步局面、模型调用及重试耗时、所有解说文本、语音原文件和播放时间线；支持回放与整局下载。

## 首版范围与实现者建议

以下为实现者建议，并非用户已指定的技术选型。首版完成可本地运行的前后端、合法棋局规则、真实 API 适配、历史回放、持久化及投票。不包含平台上架、服务器购买、自动推流、支付或数字人唇形动画。

保留已有模板页面和模块，新增观战首页并替换默认入口与模板底栏。新首页不依赖 uniCloud 登录或数据库初始化，避免未绑定云空间时无法观战。

前端使用 uni-app 的 view、text、image、button、scroll-view 和通用 CSS；通用业务不使用 DOM、浏览器存储或浏览器专用音频接口。API 封装使用 uni.request，音频封装使用 uni.createInnerAudioContext，存储使用 uni 存储接口。网页直播展示模式可使用条件编译。避免把复杂 SVG、WebGL 或浏览器专用画布作为核心棋盘依赖。

## 服务端与持续对局

使用用户指定的 uniCloud 数据库存储全部正式数据，不引入 SQLite 或 MySQL。建议新增独立 Node.js 常驻服务，由常驻循环驱动对局；HTTP 请求仅查询状态或提交投票，不驱动落子。部署要求常驻进程，不能以网页定时器或会休眠的短时云函数代替。常驻服务负责公开 API、管理员 API、模型调用与语音编排；uniCloud 云函数作为受保护的数据访问网关。

用户最新确认采用两张核心业务表：

- `xq_models`：每个大模型一条配置。
- `xq_games`：每局一条记录，所有步骤、请求记录、解说、音频索引及播放事件作为结构化 JSON 嵌入同一记录。普通开局、残局、导入棋谱和续弈共用这张表。

不再为步骤、调用、解说、音频、事件和导出分别建表。音频二进制放 uniCloud 云存储，JSON 保存 fileID 和文件元信息。投票去重与调度租约属于独立运行机制，后续按并发需求实现，不把大量观众身份塞进棋局 JSON。schema 默认禁止观众直接读写及读取模型密钥。

通过 URL 化的 `xiangqi-store` 云函数执行允许列表中的数据操作。Node.js 用共享服务密钥签名请求正文、时间戳与随机请求编号；云端验签及防重放，不提供任意集合或查询执行接口。提供 schema、索引、无密钥初始化示例、部署和配置说明。

使用同一棋局记录的原子版本校验保存局面、步骤及事件；写入检查当前局版本、调度租约和走方。每步有递增序号和服务端时间。进程重启从已提交局面恢复；重复或迟到的响应不能再次落子。涉及多个运行状态记录的操作应在部署时验证服务空间事务能力；不能用未校验版本的整局覆盖写代替原子操作。租约定期续期，失去租约后不能提交着法；不能把云端请求失败伪装成本地保存成功。

未配置云端连接时允许显式本地演示模式，使用独立本地持久化适配器供开发和测试；绝不把演示文件作为正式数据库。生产模式必须有云函数地址和服务密钥。

建议接口包括状态、按序号补取事件、历史列表、单局棋谱、候选模型和投票。首版使用约 2 秒增量轮询（隐藏页面暂停，重新显示补齐），兼容三个目标平台；断线显示同步状态，不能假装实时。API 基址可配置，生产使用 HTTPS，并配置小程序域名白名单。

公开当前局状态在常驻服务内缓存，由落子、状态变化和定时刷新更新，避免每个观众的每次轮询都直接访问云数据库。历史分页读取，客户端断线通过局号和步数补齐。管理员停用参赛模型后，本步请求可完成；下一步若配置不可用则暂停，不能临时冒名更换棋手。新局仅从当时已启用且凭据有效的模型中选取。

## 模型接入与规则

模型配置保留 id、名称、头像路径、baseURL、model、服务端密钥引用和超时。首次真实运行至少需要两个有效模型配置；候选阵容只包含已启用配置。模型名称与实际调用配置绑定。

### 数据库模型配置与思考控制

`xq_models` 是后台维护的独立模型表，字段建议如下：

| 字段 | 用途 |
| --- | --- |
| `_id`, `display_name`, `avatar_url`, `sort_order` | 稳定模型标识、名称、形象及排序 |
| `base_url`, `model_name`, `provider` | OpenAI 兼容接口地址、实际模型名与参数适配类型 |
| `api_key`, `api_key_env` | 数据库中的密钥或环境变量引用；仅服务端读取 |
| `enabled`, `can_play`, `can_commentate`, `allow_vote` | 启用、棋手、解说及投票资格 |
| `thinking_mode` | `default`、`enabled`、`disabled` |
| `thinking_adapter` | `none`、`thinking_type`、`enable_thinking`、`reasoning_effort` |
| `reasoning_effort`, `disabled_effort` | 供应商实际支持的思考强度，以及关闭时对应值 |
| `temperature`, `max_tokens`, `token_limit_field` | 可选采样温度、输出上限及兼容参数名 |
| `timeout_ms`, `max_attempts`, `extra_body` | 超时、重试与供应商扩展参数 |
| `updated_at`, `revision` | 修改时间与配置版本 |

满足用户直接维护云数据库的用法：`api_key` 可由受信任的 uniCloud 数据库后台写入；提供可选 AES-GCM 密文格式及加密导入工具，管理员接口写入时优先加密。解密主密钥放服务端环境变量；公开模型信息只返回允许字段。管理员读取配置时仅返回是否存在密钥及掩码，更新不传密钥时保留原值。

思考控制按适配器生成请求：默认模式不发送开关；`thinking_type` 使用 `thinking.type`；`enable_thinking` 使用布尔参数；`reasoning_effort` 使用配置的强度和关闭值。不支持关闭的模型不得假装关闭成功。后台可设置此能力，不把所有供应商当成统一参数。扩展参数不得覆盖已验证的 `model`、`messages`、开关、流式选项或鉴权。

提供受管理员令牌保护的模型增改、启停和连接测试 API，以及简洁管理页。管理员令牌仅手动输入当前会话，不写入代码或 URL。用户现有后台也可以直接维护集合，无需采用该管理页。更新模型配置在下一次请求读取；正在进行的一步使用开始时的配置快照，棋局保存模型名称及配置版本，不保存密钥。

页面“思考信息”展示服务端阶段及用时，例如“请求模型”“等待着法”“校验着法”；不将模型私有推理全文公开。令牌用量与错误类别可保存供后台诊断；日志与棋谱不记录密钥及完整推理。

服务端按当前局面生成合法动作列表，发送棋盘、最近棋谱和动作编号，请模型只返回所选动作的结构化结果。规则覆盖车马炮象士将兵、蹩马腿、塞象眼、炮架、过河、九宫、将帅照面和不能自陷将军。

建议单次调用超时 45 秒，最多三次尝试；连续非法输出判负。单方独立请求超时耗尽判负；明确的共同供应商故障或配置错误进入暂停状态并退避重试，页面显示原因，不能自动制造落子。绝不暗中调用象棋引擎代下。

将死或无合法着法判负。首版使用明确标注的简化和棋规则：三次同局面且同走方、连续 120 半回合未吃子、总计 400 半回合；不宣称实现完整竞赛长将长捉裁定。规则阈值可配置，计入棋局记录。

## 页面与演出

用户补充确认：只需竖屏，网页亦保持同一竖屏构图，不做桌面信息面板或侧栏。尽力贴近参考截图的游戏场景、灰绿石质棋盘、厚实立体棋子和人物画面；避免仪表盘、卡片堆叠及普通网站按钮的观感。按上方棋手形象场景、棋盘、棋盘下沿三个游戏按钮、简洁解说字幕、下方棋手形象场景布局。历史棋局、从头回看、下局投票替换截图原有按钮，点击仅打开画面内浮层。双方均显示实际图片，不用字母头像代替；素材可配置。通过落子轨迹、落地反馈、思考状态、战术特效与适量环境动效提升直播观看体验，保持棋盘清晰。未提供形象时使用明确标注的临时素材，不冒充官方授权。参考截图裁切仅用于本地设计预览，正式发布替换成独立素材。

棋子移动展示起终点与轨迹，随后落地音效、报招、解说。模型思考状态由服务端提供。将军使用规则计算后的特效；叫杀仅在有战术搜索证明时显示，首版允许不显示未经证实的叫杀。报招使用规范着法处理前后同类棋子等歧义，不由解说模型猜。

进一步视觉调整（以用户最新更正为准）：三个按钮位于红方豆包 banner 下方的屏幕最底部，解说条在豆包 banner 上方，降低直播底部遮挡对核心画面的影响。双方形象都有轻微浮动或呼吸动效，名称与形象之间放完整金色发光圆环，展示本步思考时间及简短状态；不展示模型私有推理过程，真实状态来自服务端。绝杀演出区别于普通将军，使用蓄光、斩光、环形冲击波、短促位移震动、金色书法落印和收尾声音；尊重减少动态效果设置。设计预览手动触发的特效必须标明为演示，实际版本仅由已确认终局事件触发。

长距离移动不能匀速滑行：先抬起、放大与偏移阴影，再加速掠行、减速悬停，快速重落并轻微回弹；落地一刻同步短促棋盘震动、接触环和少量尘点。炮横跨六路作为验收样例。当前本地预览提供 48 kHz 木质撞击合成 WAV，取代原有扫频电子音，包含短时噪声接触、固定频率木质共振和短余响，不宣称为实物录音。音频预加载后与落地接触帧同步；正式小程序使用相同素材与平台音频封装，避免依赖网页音频合成能力。

走棋提示和预览操作提示统一放入解说框，取消棋盘下方独立提示行，并收紧间距。双方图片适度缩小，豆包保留完整头部、脖颈与上半身；人物浮动不能导致这些区域再次被裁切。

提供静音切换；首次点击启用音频，保留声音被平台限制的提示。解说失败不阻塞棋局。音频有优先级和有效期，报招与解说顺序播放，积压时丢弃过时解说；重连不补播全部旧语音。回放不与实时音频混播。

网页提供直播展示模式，隐藏交互面板，维持固定竖屏比例供 OBS / 直播伴侣采集；服务本身不负责抖音推流。

## 解说与语音

使用单独的解说文本模型配置，再接火山豆包语音合成。建议以“亲切女声 2.0”为试音候选，准确 voice id、资源权限及鉴权参数根据实际账号和官方文档核实，不预设可用权限。

解说输入仅包含已确认的局面、着法和规则事件；普通落子简短播报，关键局势适度展开，不虚构引擎分数或必胜判断。语音在服务端生成并缓存，通过音频 URL 提供给终端；固定报招和提示可预生成。文字模型与语音服务使用分别配置的凭据。

所有生成成功的解说和报招语音均上传 uniCloud 云存储并持久化 fileID；服务商临时地址不能作为唯一存档。音频索引保存格式、时长、字节数、SHA-256、音色、语音模型及非敏感配置版本。按需换取播放地址，地址过期后可重新获取；不可覆盖原始文件。字幕有生成中、成功、失败状态，语音另有合成中、上传中、已归档、失败状态，支持后台重试。解说修订或重新合成生成新版本，保留直播当时使用的版本。

没有密钥时提供独立标记的本地演示模式，使用确定的合法示例棋谱。演示不调用付费接口，不显示为真实 AI 正在对战；真实服务断线不能自动切换成未标注的模拟直播。

## 回放与历史

历史页列出双方、开局时间、结果和步数，点击可查看完整棋局。当前局“从头回看”将本地游标置于初始局面，展示上一步、下一步、当前步 / 最新步及返回直播。

回看期间继续同步实时事件，但不改变用户游标；跨局开新场时仍可看完旧局，返回直播进入新的当前局。回放棋盘严格从持久化棋谱重建，不能用另一套随机过程替代。

### 每步的完整档案

| 记录 | 持久化内容 |
| --- | --- |
| 棋局根字段 | 双方无密钥配置快照、初始局面、规则版本、开局/结束时间、结果及原因 |
| `steps[]` | 唯一半回合序号、走方、起终点、吃子、规范着法、落子前后 FEN、将军/终局判定 |
| `steps[].calls[]` | 模型执行及重试、实际 think 设置、开始/结束时间、耗时、状态、错误和可用 Token 用量 |
| `steps[].commentaries[]` | 本步所有报招与分析文本、版本、生成耗时及直播选用状态 |
| `steps[].commentaries[].audio[]` | 语音原文件 fileID、时长、大小、摘要、合成和上传耗时、音色及播放偏移 |
| `steps[].events[]` | 本步动画、字幕和声音事件，与根级事件按唯一序号合并 |
| 根级 `calls[] / commentaries[] / events[]` | 开场、暂停、总结等不属于具体一步的记录 |
| `pending_step` | 正在请求或重试但尚未形成合法落子的调用档案 |

所有时间戳保存 UTC 毫秒，页面按本地时区显示；单次调用耗时用服务端单调时钟计量。每次尝试开始前先将调用写入同局的 pending_step 或整局 calls，返回后补齐结果，失败尝试也保留。重启后将未完成调用标为中断，不能静默删除。使用局号、步号、尝试号、事件 ID 去重，只有通过规则校验且事务提交成功的着法进入正式棋谱。

区分棋手 API 请求耗时、含重试的整步决策耗时、规则校验耗时、解说生成耗时、语音合成耗时、上传耗时及等待播放时间。页面“思考用时”是服务端观测到的决策时间，不冒充供应商内部纯推理耗时；供应商未返回的首 Token 或思考耗时保存为 null，不编造数值。不能把解说生成和语音合成时间计入棋手思考时间。

归档包含开场、停顿、错误提示、终局总结等不对应某一步的解说，以事件关联而非强制绑定不存在的步号。直播因积压而跳过的解说或语音仍保留并标记未播。模型私有推理全文、Key、Authorization 不进入棋谱或公开下载；如需后台保留最终模型输出，只保存已脱敏的最终回答及校验结果。

### 回放时序与后台下载

回放支持逐步查看及按原始节奏自动播放，使用持久化时间线和当时选用的解说/音频版本，不重新调用模型生成。提供是否播放思考等待、是否开启原声的选项；跳步、切局和返回直播时停止旧音频，按当前位置重新调度。记录的是服务端统一播放计划，不宣称等同每位观众设备上实际播放的时间。没有语音或合成失败时仍可回放棋盘与字幕，并明确标注缺失资源。

后台按局、模型和步号查看调用与耗时，支持单个音频下载，以及整局异步 ZIP 导出。导出包以单份可完整导入的 `game.json` 为主，包含校验用 `manifest.json` 及 `audio/` 中的实际音频文件，可另附解说字幕与耗时 CSV；禁止只导出过期播放链接。manifest 记录导出版本、每个资源的相对路径、字节数、SHA-256 和缺失项。正在进行的棋局按明确的截止事件序号生成一致快照，包内注明尚未完局；导出进行中不能把新事件混入旧快照。

导出接口仅管理员可用，按云存储 fileID 获取允许的资源并流式打包，限制同时导出数量、单包大小和处理时间。状态包括生成中、就绪、部分资源缺失、失败；临时 ZIP 下载任务保留一小时并存本机缓存，服务重启后可重新生成，原始棋谱和音频保存在 uniCloud；存在缺失文件时不报告为完整导出。音频及棋局默认不自动删除，管理员显式清理时先检查引用，不能因临时播放地址失效而删除原文件。共享的固定提示音可按摘要去重存储，但每次播报事件独立记录。

## 残局、导入和续弈

支持摆棋及 FEN 导入建立残局，选择双方模型与先走方；保存为 `type=endgame` 的棋局草稿。开始前验证棋子数量、位置、将帅、九宫、象的范围、先走方及局面合法性，再由双方大模型继续对战，过程使用相同的 steps 归档和回放。

支持单份 game.json 或含音频 ZIP 的导入，校验 schema_version、FEN 和完整着法序列，不信任导入文件的状态、权限或可执行指令。重新分配棋局 ID，保留原 ID 作为来源；上传音频并重写 fileID 后原子保存整局。文件校验、局面规则校验及资源齐备性分别报错。

导入棋局可仅回放，也可从指定步骤创建续弈新局；新局将来源步骤的局面作为 initial_position，保留 source_game_id 和 source_step_seq，不修改原棋局。

普通记录将完整档案内嵌。接近服务空间的实际文档大小限制时，完整 JSON 外置云存储并在同一棋局记录的 archive 中保存 fileID、摘要及版本；上传成功且原子版本校验通过后才能切换，读取和导出必须支持两种模式。语音生成和解说追加也参与版本校验，避免旧快照覆盖新落子。

## 下局投票

建议按当前局对应的下一场投票，每位观众每轮一票，选一名模型；前两名不同模型参赛，平票按稳定模型 id 排序，候选少于两名时使用配置的默认双方。开新局时事务性封存上一轮并创建新投票轮；临界请求不能落入错误轮次。下一局红黑按场次交替安排。

首版匿名网页身份使用持久化访客标识加服务端限流和去重，只是轻量投票，不能保证一人一票或抵抗清除存储。后续微信与抖音登录通过平台身份适配，在服务端换取统一会话。前端不得指定可信用户身份或修改总票数。
